# Integration guide — v1.1.1

## Who should read this

Host apps upgrading from `1.1.0` to `1.1.1` on Android. Most hosts upgrade without code changes.
A host that passes `onLivechatSessionChange` as a trailing lambda must name it.

## Breaking changes

| Area | Before (1.1.0) | After (1.1.1) | Action |
|------|----------------|---------------|--------|
| `ChatbotBottomSheet` parameters | `onLivechatSessionChange` was the last parameter, so it could be passed as a trailing lambda | `sessionMetadata` is the last parameter; a trailing lambda no longer compiles | Pass it by name: `onLivechatSessionChange = { … }` |

## Migration steps

1. Depend on the release:

   ```kotlin
   implementation("ai.askdiverge:diverge-sdk:1.1.1")
   ```

2. If the host calls `ChatbotBottomSheet(…) { info -> … }`, move the lambda inside the parentheses
   and name it:

   ```kotlin
   ChatbotBottomSheet(
       chatbotCallbacks = callbacks,
       onDismiss = { isChatOpen = false },
       onLivechatSessionChange = { info -> … }
   )
   ```

3. Optional: pass `sessionMetadata` to attach what the host's CS systems need to identify the
   visitor. Create one `ChatbotSessionMetadata` at app start, pass it to every sheet, and call
   `setMetadata(mapOf(…))` or `setSignedMetadata(jwt)` at any time. See "Session metadata" in the
   [README](../../README.md#session-metadata) for the value rules, signed tokens and when to call
   `clear()`. The default, `null`, sends nothing.

## New permissions / privacy

- Manifest permissions: none declared by the library. The host supplies `INTERNET`.
- Session metadata is sent to the Diverge backend and shown to live agents with the conversation.
  The host decides what it contains; send only what the host's privacy notice covers. The SDK keeps
  it in memory only and writes nothing to disk.

## Backend requirements

- Session metadata needs `PATCH /api/v1/chat/session` on the Diverge backend. Without it the
  request is refused, the metadata is dropped and the chat works as before.
- Signed metadata also needs the chatbot's RS256 public key registered in the Diverge dashboard
  (Developer → Signed metadata). Until then, signed tokens are refused and dropped.
